01

Card anatomy

The card is ours on every theme and every page. The only thing taken from the store is its font family, which crosses the shadow boundary for free. Hover a card to see the second image and the add-to-cart button.

Second image on hover

Cross-fades to the product's second image over 350ms. Every card on this page has one, so you can hover any of them. A product with only one image simply does not transition — never a blank frame.

The sold-out card is the one exception: no hover image and no add-to-cart, since neither leads anywhere.

Add to cart

Shown here as the floating button on hover. There is a second option — a button under the price — compared side by side in the next section. We need you to pick one.

Sold out

Badge top-left, image at 55% opacity, no ATC button and no hover image. Position is never demoted — color relevance decides ranking. Merchant can hide these entirely.

Image ratio and fit

Both are merchant settings — see section 06, where they are live. The card has to hold its shape at any of them, from a 16:9 band to a 2:3 portrait.

02

Add to cart — two options

Hover each card. We need to pick one, and it is a straightforward choice rather than something that needs designing from scratch.

A — floating, on hover
  • Cotton Shirt — Dusty Rose $295.00
B — under the price, always visible
  • Cotton Shirt — Dusty Rose $295.00

A — floating button

Keeps the card clean and lets the product fill the frame. The trade: it is invisible until hover, so a shopper may not know it is there — and on mobile there is no hover, so it has to be permanently visible anyway.

B — button under the price

The more common pattern, and the more discoverable one. Costs about 40px of height per card, which means slightly fewer products visible before scrolling. Identical on mobile and desktop.

Our suggestion

B, unless the cards need to stay minimal. Add to cart is how this feature proves it drives sales, so making it obvious matters more than keeping the card spare. Happy to go with A if you prefer the cleaner look.

Either way

Products with multiple sizes or variants will send the shopper to the product page instead of adding directly — we cannot guess which size they want.

Loading — three options

Each says something different, so the choice is about what matters most in that second.

Skeleton shows the shape of the answer, so the grid doesn't jump when results land. The safest, and the least memorable.

Hue sweep is branded — a color bar under the header plus a pulsing swatch of the searched color.

Color settle shows tiles resolving from grey into the searched color, one at a time. It is the only one that says what is actually happening — matching products to a color — and it uses the shopper's own color, so it looks different on every search. The uneven timing is deliberate: results arriving, not a progress bar.

Any two can combine (sweep bar above skeleton cards, for instance).

Empty is not an error

Says why, and offers the next action. Hoppn shows "0 Results" during import, which a shopper cannot tell apart from a broken app. Never show a bare zero.

Header

Hex bubble top-left with the searched color and live match count. Top-right is "Change Color" with the gradient wheel, as requested.

A picked color shows its hex, as above — the search API returns the matched hex, not a friendly name. Showing "Dusty Rose" instead is a small follow-up, and worth doing: a name reads far better than #C9839E.

Still open

The empty and error states work but are plain text — they would carry a small mark or illustration well if you want one. Same for the "added to cart" confirmation.

Mobile

The overlay is full-screen on mobile — there is no visible page behind it, so it behaves as a screen, not a modal. Tested on iPhone 14 Pro Max, iOS 26.6, Safari.

Touch targets stay 44px

The chrome shrinks but Close and Change Color stay 44×44. The swatch moves onto the Change button and the label is dropped, so the header never carries the color twice.

No hover on touch

Add-to-cart is always visible on mobile. The second image needs a different trigger — design decision needed: tap-to-swap, a small carousel dot, or skip it on mobile entirely.

Two columns

Below 600px. Capped deliberately — smaller than this and a shopper cannot judge a color, which is the only thing this product does.

Verified

Scroll position is preserved on close, the page behind never moves, and the theme's DOM is byte-identical after close. Already tested on real devices.

Technically confirmed

Gap is already a CSS variable (--sc-gap), so it is nearly free. Columns are currently fixed at three breakpoints and become variables. Mobile gets its own value — the overlay already has a mobile block.

What this asks of the design

The card must stay legible at 5 across on desktop and 1 across on mobile. Title clamps to 2 lines at every size; price never wraps.

Deliberately not merchant-editable at launch

Colors, fonts and corner radius. The card's internal spacing IS editable — see section 05.

A second group in the app embed, under a Product card header. Image ratio is the one that changes the look most, so it is first. Everything below is live — change a setting and the three cards update.

  • Norse ProjectsKnit Sweater — Sage$225.00

The three products are deliberately different shapes — tall, wide and square — so a ratio change is visible rather than theoretical. On a real store they are usually all the same shape, which is why "Adapt" looks identical to a fixed ratio there.

Why image ratio matters most

Adapt to image reads the proportions of the store's own photography and applies them to every card — so a store shooting square gets square, one shooting 4:5 gets 4:5, with no setting to choose. Rows stay aligned either way.

A fixed ratio overrides that when a merchant wants a specific shape regardless of their source images.

One ratio, not one per card

"Adapt" takes the ratio from the first result and gives every card the same one. A ratio per card is the obvious reading and it produces a grid nobody wants — measured on four mixed-shape products, the titles landed at four different heights because each card hugs its own image.

Fit is ignored under "Adapt": the frame already matches the source, so there is nothing to crop or letterbox.

Brand name is free

It comes from the same request that already fetches prices, so showing it costs no extra load. Off by default — most fashion stores sell one brand, where it would repeat on every card.

Hidden lines take their space with them

Turning off the title removes its spacing too, rather than leaving a gap where it was.

Adapt is the default

A merchant who never opens these settings gets their own photography's proportions, which is right far more often than a square we picked for them. A fixed ratio is there for stores with inconsistent source images.

Reduced motion

Every animation here is wrapped in prefers-reduced-motion. Any new motion must have a still fallback.

Accessibility baseline

Focus trap while open, Escape closes, focus returns to the element that opened it. New controls need a visible focus state — not just a hover state.

Light and dark

The overlay is currently light-only. Decision needed: do we follow the store's own scheme, or stay light everywhere?

Scope note. Merchant-editable colors, fonts and corner radius are deliberately out for launch. What ships is layout (cards per row, gap) and the card itself (image ratio and fit, which lines show, text spacing).
